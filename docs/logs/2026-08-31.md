### 1. Validated Phase 0 metrics against the repo
Re-ran every count. Confirmed: 74 models, 0 enums, 122 routes, 18,329 lines of

### 2. Verified the critical defect claims
Confirmed first-hand: fabricated IRN (32-bit hash + `Date.now()` behind a
comment claiming SHA-256); no year-end close (`fiscal-years` is 57 lines, GET and
POST only; `isClosed` never set true); cash flow group-name mismatch; payroll
float math (11 × `Math.round`, 0 × Decimal); tenancy is manual (0 `$use`,
0 `$extends`, 0 RLS; 110/111 routes use `withOrgAuth`).

### 3. Refuted a central Phase 0 claim
`applyLedgerEntries` is **not** the single posting choke point.
`migration/tally.ts:697-718` inlines its own `applyLedgerBalances` with **no
balance check, no org scoping, and `if (!nature) continue`** — reintroducing the
exact bug the main function documents having fixed. Logged as **D-22**.

### 4. Four new defects found, two more severe than anything in Phase 0
- **D-23 (critical)** — `decideInvoiceEntries` has **no `CREDIT_NOTE` branch**;
  credit and debit notes post **backwards**, increasing revenue and receivables.
  `bills/route.ts:22` types `type` as bare `z.string()`.
- **D-25 (critical)** — manufacturing **double-counts** inventory: the
  `Stock-in-Hand` ledger is inside `assetLedgerTotal` while derived `stockNow` is
  added on top. The code comment asserting otherwise is false.
- **D-24 (critical)** — `valuation.ts` applies `asOf` only to cost layers, not
  quantities, so historical valuation is fiction and the periodic adjustment
  **cancels to zero** for weighted-average items.
- **D-26–D-29** — approvals dead-end for INVOICE/PURCHASE_ORDER; batches never
  decremented; leave quota unenforced; two reconcilers with the UI calling the
  **untested** one.

### 5. Original experiments run
- **Money:** `SUM()` over a TEXT column silently returns `real`; TEXT sorts
  lexicographically (`-100 | -5 | 10 | 2`); INTEGER sorts and sums exactly.
- **Range:** INT64 at scale 4 = ₹922 lakh crore (~3× India's GDP).
- Confirmed earlier findings: `DECIMAL(18,4)` stores as `real`;
  `PRAGMA foreign_keys` defaults OFF; STRICT rejects type mismatches.

### 6. Delegated research (verified, with citations)
- **`synchronous=FULL` is 63× slower than `NORMAL`** (5.01s vs 0.08s for 2,000
  commits) and NORMAL cannot corrupt in WAL → **revised the earlier
  recommendation**.
- **`BEGIN IMMEDIATE` is mandatory** — a deferred transaction upgrading
  read→write returns `SQLITE_BUSY` *instantly regardless of busy_timeout*, and
  `setAutoCommit(false)` issues a deferred begin.
- **SQLite does not poison a transaction on constraint violation** (unlike
  Postgres) — catch-and-continue would silently commit partial journal entries.
- `busy_timeout=0` lost **900 of 1200** concurrent writes; driver default is
  3000, CLI default 0.
- A single leaked reader grows the WAL unboundedly (6 MB WAL / 12 KB DB).
- JDBC driver resolved: `org.xerial:sqlite-jdbc:3.53.4.0`, Apache-2.0 + BSD-2,
  **real JPMS module**, Online Backup API exposed, all 5 target platforms
  incl. Apple Silicon. jlink needs **`--bind-services`**.
- The `decimal_*` SQL extension is **absent from the driver** — a TEXT-decimal
  design is unimplementable.

Analysed the proposed sequence against Phase 0 dependency facts. **Adopted two of
the user's changes as improvements over my earlier draft:**
- splitting module/build (P4) from licensing (P3) — build is compile-time,
  entitlement is runtime; merged they were too large to land safely;
- pairing year-end with financial reporting — they are one design conversation.

**Raised three sequencing problems** (`ROADMAP_SEQUENCING_ANALYSIS.md`):
1. **Entitlement enforcement must land inside Phase 4**, not after. ADR-002
   layer 2 is a guard *in the write path*; building P5–P6 without it means
   retrofitting across finished features — the exact drift that left 55 of 71
   reference routes unguarded.
2. **Inventory before sales/purchase is backwards under perpetual costing.**
   COGS relieves stock against documents; returns attach to credit notes; the
   `pending = invoiced − dispatched` derivation needs invoices. Split into
   masters (P7, with documents) and costing (P8, after).
3. **Late security/concurrency testing is a schedule cliff.** `BEGIN IMMEDIATE`,
   explicit rollback and WAL/recovery behaviour are architectural and apply from
   P2. Redefined P15 as a certification gate, not first occurrence.

Also flagged P8 as overloaded (four domains, one gate) → split into taxation and
banking; and noted HR/payroll carries an unresolved blocking decision (B-5), so
its v1 scope is a business call.

Net: 14 proposed phases → **16 baseline phases**; no phase reordered in
principle.
